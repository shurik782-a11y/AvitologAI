# Развёртывание AvitologAI на своём сервере

Подробная инструкция для VPS / своего хоста (Ubuntu 22.04+). Репозиторий: `https://github.com/shurik782-a11y/AvitologAI`.

---

## 1. Что нужно заранее

| Что | Зачем |
|-----|--------|
| Сервер с Docker + Docker Compose | запуск приложения |
| Домен с HTTPS (nginx / Caddy / Cloudflare) | Telegram WebApp требует HTTPS |
| Токен бота (@BotFather) | Telegram |
| Ваш Telegram user id | `ADMIN_IDS` |
| Ключ OpenRouter | генерация текста/фото |
| (Опционально) Postgres | продакшен-БД; без него — SQLite в volume |

Узнать Telegram ID: напишите боту `@userinfobot`.

---

## 2. Переменные окружения

Создайте файл `.env` в корне проекта (рядом с `docker-compose.yml`):

```env
PUBLIC_BASE_URL=https://avitolog.example.com
TELEGRAM_BOT_TOKEN=123456:ABC...
ADMIN_IDS=123456789
OPENROUTER_API_KEY=sk-or-...
ORCHESTRATOR_MODEL=openrouter/free
VISION_MODEL=openrouter/free
IMAGE_MODEL=black-forest-labs/flux.2-flex
DATA_DIR=/data
# Продакшен — Postgres (пример):
# DATABASE_URL=postgresql://avitolog:SECRET@db:5432/avitolog
# Локально / один контейнер без Postgres — оставьте пустым (SQLite в /data)
DATABASE_URL=
```

Важно:

- `PUBLIC_BASE_URL` — **без** слэша в конце, именно публичный HTTPS URL.
- `ADMIN_IDS` — через запятую, если несколько админов. Без этого в проде API будет открыт (режим разработки).
- XML-фид Авито доступен по URL с `?token=` без Telegram-авторизации (так задумано).

## 3. Быстрый старт через Docker Compose

В этой папке уже есть пример `docker-compose.selfhost.yml`.

```bash
cd AvitologAI
cp .env.example .env
# отредактируйте .env

docker compose -f docker-compose.selfhost.yml up -d --build
```

Проверка:

```bash
curl https://avitolog.example.com/api/health
curl https://avitolog.example.com/api/telegram/status
```

После старта приложение само:

1. ставит webhook на `{PUBLIC_BASE_URL}/api/telegram/webhook`
2. ставит Menu Button WebApp
3. на `/start` у админа показывает кнопку открытия Mini App

В BotFather дополнительно укажите Web App URL = `PUBLIC_BASE_URL`.

## 4. HTTPS (Caddy — самый простой вариант)

Установите Caddy и проксируйте на контейнер `127.0.0.1:8000`:

```caddyfile
avitolog.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

Или nginx:

```nginx
server {
    server_name avitolog.example.com;
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 5. Volume и данные

- `/data/uploads` — загруженные и сгенерированные фото
- `/data/feeds` — кэш XML
- при SQLite: `/data/avitolog.db`

Сделайте бэкап volume регулярно.

---

## 6. Подключение Авито (без API)

1. В приложении: Настройки → Avito / Фид → категория, адрес, телефон → Сохранить.
2. **Скопировать URL** фида.
3. В кабинете Авито → Автозагрузка → вставить URL.
4. В чате соберите креатив → **Утвердить** → объявление попадёт в XML.
5. Авито подтянет фид по своему расписанию.

Client ID / Secret нужны только для API upload и метрик.

## 7. Локальный запуск без Docker (разработка)

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
pip install -r requirements.txt

cd web && npm install && npm run build && cd ..
uvicorn app.main:app --reload --port 8000
```

Frontend в режиме hot-reload:

```bash
cd web
npm run dev
```

## 9. Частые проблемы

| Симптом | Что проверить |
|---------|----------------|
| Бот молчит | `TELEGRAM_BOT_TOKEN`, `PUBLIC_BASE_URL`, webhook `/api/telegram/status` |
| «Нет доступа» | `ADMIN_IDS` = ваш Telegram id, открывать Mini App из бота |
| Фото не в фиде | абсолютные HTTPS URL → `PUBLIC_BASE_URL` |
| init_db / DATETIME | используйте свежий код (`TIMESTAMP WITH TIME ZONE` для Postgres) |
| Баланс н/д | `OPENROUTER_API_KEY` |
